Problem

Thread view merges updates by ID; transcript rendering replaces only the last item. A late update to an earlier tool can render twice.

Solution

Keep the existing webview seam; concentrate snapshot and streamed-item ordering in one Thread transcript module, not another public adapter.

Benefits & tests

Locality: one merge rule. Leverage: display, jump and plan agree. Test the interface through a streamed non-tail update in the rendered Thread.

Problem

AgentManager owns statuses, but imports their type from the webview protocol. The view mirrors the list and sends it once per Agent on each change.

Solution

Keep status meaning in the existing Agent module; have the VS Code view adapter forward its snapshot once. Remove the mirrored status state.

Benefits & tests

Locality: one status owner. Leverage: Settings receives one consistent list. Test the manager interface and one forwarded view message.
