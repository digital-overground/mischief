# Connect remote clients to the existing Host over Tailscale

Remote access is an opt-in connection to the same ACP-owning Host, not another runtime. The first remote client is a second macOS app that connects directly to the Host's Tailscale address, following Orca's connection model rather than configuring Tailscale Serve or exposing a public listener. Keep the local Unix socket separate; do not open any network listener until remote access is enabled, and restrict the listener to the intended tailnet address. The Host must remain available after login for paired clients when remote access is enabled, even with the local app closed.

Tailscale supplies an encrypted private path, **not** Mischief authorization. On the Host Mac, a user creates an Orca-style pairing link or QR; possession of that invitation is sufficient to pair, without a second confirmation click. Treat invitations as secrets and limit their validity. Pairing pins Host identity and issues a separate revocable credential per device; reject a changed Host identity and disconnect a revoked device. No tailnet-wide implicit access. The first remote release allows text prompts, streaming, permissions, cancellation, and Thread creation/control in existing Host Workspaces. It does not open Host-side file links or diffs on the client, upload client files/images, manage Workspaces, install Agents, change credentials, or administer the Host. Local and remote clients see the same Thread state; a disconnect does not cancel Agent work.

Before exposing the listener, specify and test the exact pairing token lifecycle, Host-identity verification, credential storage, access-control checks, listener binding across tailnet address changes, and reconnect/revocation behavior. A private tailnet alone is not a substitute for those checks.
