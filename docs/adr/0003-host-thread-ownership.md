# Make the local Host the sole owner of live Threads

Phase 3 moves ACP connections, running turns, and Thread writes from VS Code windows to one per-user Mischief Host. The macOS app and VS Code will both be clients of that Host; closing either client, including quitting the app, must not stop an active turn. This replaces the per-Workspace-window writer rule in [ADR 0001](0001-profile-database.md) **only at cutover**. Until then, VS Code remains the owner, and the existing app-launched companion Host remains read-only for Threads. A second client must never call ACP `session/load` on an already-owned session.

Start with the Default VS Code profile; do not merge other profiles implicitly. The Host needs its own private application-support directory for state and Agent installations, and a local-only client connection usable without the macOS app. Use a per-user background process from a stable, signed location outside the replaceable app bundle, and a Unix-domain socket in a private directory for local clients. Same-user local processes are trusted; validate requests and reject incompatible versions. Start on local demand and keep running until logout; enabling remote access also starts the Host at login. No app-child stdio or network listener may own live Threads. Acquire exclusive profile ownership before accepting work, reclaim stale endpoints only after proving the old owner is gone, and reject incompatible clients rather than falling back to a second ACP owner. Stage Host updates until running turns finish; a crash or reboot marks unfinished turns interrupted for manual resume, never automatic prompt replay. If no client is connected when ACP asks permission, keep the turn waiting for a response rather than granting or denying it automatically. See [ADR 0004](0004-tailscale-remote-clients.md) for the separate remote-access decision.

Migrate only when all relevant VS Code windows are closed and their turns have finished: back up the Default profile, copy and validate records, then retire the old _active_ Thread index so legacy extensions cannot automatically restore those registered sessions. Do not delete the backup or Agent-owned session history. Require an upgraded extension after cutover; prove that a legacy extension cannot manually reopen the same Agent session from history before shipping the migration. If the Host is unavailable or incompatible, upgraded clients fail visibly and **never fall back** to opening ACP locally. Preserve the current extension until its replacement passes create, restore, prompt, queue, cancel, permission, and transcript checks with both clients connected.
