# A live code-and-decision advisor for Mischief

**Status:** revised proposal, not an implementation. **Goal:** catch avoidable complexity _while_ a Thread's Agent plans and edits—think Ponytail-style review, not tool safety or permission approval.

## Recommendation: reuse before building

First try [Abide](https://github.com/coldteadotai/abide) with a few approved Ponytail checks in a real MagPi/Mischief Thread. It already checks `AGENTS.md` / project rules against each edit and the turn diff using Jev, and can give the Agent corrective feedback; it advertises Pi, Claude Code and Codex integrations. Verify it actually works through **MagPi's Pi subprocess over ACP** rather than assuming that an Agent-side integration works in this configuration. If it does, don't rebuild its rule engine in Mischief. Build only the missing Mischief value: a **Thread-scoped, cross-Agent view of timely findings**, if that still matters. [Abide hooks and supported Agents](https://github.com/coldteadotai/abide); [Mischief Agent ownership](../../CONTEXT.md).

Other close precedents (primary sources):

| Tool | Useful precedent | Gap relative to this request |
| --- | --- | --- |
| [OMP Advisor](https://omp.sh/docs/advisor) | Watches plans, reasoning, tool activity and responses; sends rate-limited `nit` / `concern` / `blocker` notes; project `WATCHDOG.md` supplies priorities. | It runs a _separate generative reviewer_, not a System One classifier. Its in-loop steering relies on OMP's own Agent runtime. |
| [Abide](https://github.com/coldteadotai/abide) | Per-rule Jev questions on each edit/turn, compiled from project guidance or maintained manually; returns repair feedback to the Agent. | Agent-specific installation; does not provide Mischief-native Thread presentation. Best pilot before new code. |
| [jev-lint](https://github.com/ckorhonen/jev-lint) | Post-edit hooks, cheap pattern gates before Jev, narrowly defined rule packs, labeled examples for evaluating rules. | Similar per-Agent hook installation and feedback; strong reference for calibration, not a reason to add another generic rules framework. |
| [jev-pref](https://github.com/doeixd/jev-pref) | Project-specific semantic rules applied to code hunks; agent-facing review and structured JSON output. | Works well for explicit review of diffs; not itself a live Mischief Thread observer. |
| [Ponytail review skill](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail-review/SKILL.md) | Focuses **only** on avoidable complexity: delete, stdlib, native, reuse, YAGNI, shrink. Each note names a location and replacement, or says nothing when already lean. | A rubric, not a live observer; it must be turned into testable questions with evidence. |

## What Mischief can actually see

`src/threads/acp/acp.ts` translates ACP messages, plans, thoughts, and tool updates (IDs, status, optional input, locations and diffs). `src/threads/threads/threads.ts` assembles the transcript and emits `Threads.onChange({ type: "transcript", threadId, item })` for observed Agent items, including for nonselected local Threads. **Plan updates and file diffs are optional Agent-provided data**, not guarantees. Partial streamed assistant text or thoughts are not a reliable standalone account of a decision; prefer a completed plan, an actual edit, and task context. [ACP translator](../../src/threads/acp/acp.ts); [Thread event model](../../src/threads/threads/models.ts); [transcript reducer](../../src/threads/threads/transcript.ts); [ACP tool updates](https://agentclientprotocol.com/protocol/v1/tool-calls).

One important seam missing from the previous proposal: the locally created **user prompt and turn completion** are not always delivered as `ThreadsChange` transcript events. `Threads.prompt` adds its user item and usually emits an untyped change; an Agent echo can be reconciled without emitting a transcript change. A cross-Thread advisor needs small `turnStarted` / `turnFinished` events (with Thread ID and prompt/outcome), or a similarly direct observer in `Threads`. Don't derive task context from the _selected_ snapshot; another Thread may be running. [prompt/turn flow](../../src/threads/threads/threads.ts); [identity reconciliation test](../../src/threads/threads/threads.test.ts).

Mischief's existing “steering” is a **queued user prompt**. Sending it immediately cancels the active turn; it is not a quiet in-turn system note. An Agent-side post-edit hook can deliver an immediate repair suggestion more faithfully than ACP currently lets Mischief do. Don't auto-cancel or silently inject a fake user prompt to emulate OMP. [Thread queue/cancel](../../src/threads/threads/threads.ts); [OMP advisor delivery](https://omp.sh/docs/advisor).

## Suggested quality-review pilot (if Abide is insufficient)

1. **Pick 2–3 human-approved, falsifiable Ponytail rules**, not every paragraph in `AGENTS.md` or the entire skill. Start with (a) speculative new abstraction/config for one use, (b) reinventing an **identified** existing helper, (c) a new dependency/custom implementation when a **named** stdlib or native feature works. Attach source guidance, trigger, needed evidence and a one-line replacement. Never flag necessary validation, security, accessibility, correctness, or the smallest useful test as “bloat.” A vague “could this be simpler?” is not an actionable finding. [Ponytail skill](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md); [review rubric](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail-review/SKILL.md); [local repo standards](../../CONTEXT.md).
2. **Watch useful milestones, not every token/tool.** On a substantive plan update, evaluate only decisions explicit in that plan against the user's task (e.g., planning a new generic layer for one concrete need). On a **completed edit with an attributable diff**, filter locally by changed code/imports/paths; include only the changed hunk and minimal surrounding evidence. If a rule says “reuse the existing helper,” first find a plausible helper by scoped code search and supply its path/signature; without evidence, abstain. On turn finish, optionally check a narrow verification claim against the actual test results already observed. Prefer agent-provided per-call diffs to a Workspace-wide `git diff` that may contain simultaneous human or other-Thread changes. [Mischief transcript data](../../src/threads/threads/models.ts); [ACP optional metadata](https://agentclientprotocol.com/protocol/v1/tool-calls); [Abide edit/turn distinction](https://github.com/coldteadotai/abide).
3. **Ask System One a closed, evidence-backed question.** Example state: `{ taskExcerpt, ruleId, ruleText, changedHunk, existingAlternative?, planExcerpt? }`. Ask a `choice` question with criteria for `clear_issue`, `no_issue`, `not_applicable`, and `insufficient_evidence`. Validate its typed reply; issue a note only when a calibrated rule-specific threshold and a concrete location/replacement are both present. System One does **not** write a review or discover codebase facts: Mischief supplies the evidence and formats the note. One OpenRouter `/api/v1/systemone` request may batch the few applicable questions. Gilligan demonstrates the transport, typed-question validation, cancellation, and no-LLM-fallback pattern in the local private sibling `Projects/gilligan-golf/gilligan-mono/server/src/commands/system-one-parser.ts`; reuse the pattern, not its Bun/Effect code. [System One endpoint](https://openrouter.ai/docs/api/api-reference/systemone/submit-a-system-one-request); [Jev confidence guidance](https://openrouter.ai/docs/guides/community/jev-tutorial).
4. **Deliver small, attributed feedback.** Pilot with one optional VS Code notice in the owning Workspace per distinct finding and a quiet Thread-scoped log; e.g. `Thread X · src/view.ts:42 · reuse: replace duplicate parser with src/present.ts`. Include source rule and observed code location, not model-generated prose. Deduplicate across pending/in-progress/completed updates; discard findings made stale by a later edit, turn switch or cancellation. Start user-visible only; the next experiment can be a user-approved “send suggestion to Agent” at a safe boundary. Auto-steering would need a genuine Agent-side hook or separately designed turn-follow-up semantics. [Mischief change events](../../src/threads/threads/models.ts); [existing VS Code notifications](../../src/extension.ts); [OMP note/admission precedent](https://omp.sh/docs/advisor).
5. **Calibrate before trusting it.** Collect small labeled plan/edit pairs: actual duplicated helper, justified helper, stdlib/native replacement, legitimately required abstraction, false match, missing diff, concurrent Threads, and corrected edit. Track actionable catches, false alarms, delayed/stale notes, latency and requests per turn. If a rule cannot name a real replacement or repeatedly flags justified code, reword or drop it rather than lowering a generic threshold. Start disabled/opt-in, with a user-held API key in VS Code secret storage. Send only consented bounded excerpts, no raw full transcript, thoughts or tool outputs; on unavailable/malformed response, show no fabricated verdict. [jev-lint evaluation pattern](https://github.com/ckorhonen/jev-lint); [OpenRouter provider privacy controls](https://openrouter.ai/docs/guides/routing/provider-selection).

**Flow:** `Thread prompt + plan / completed edit + relevant local code evidence → local candidate rule → one or a few typed System One judgments → optional Thread-labeled finding`. If existing Agent-side tools give better, earlier repair feedback with less work, stop there.
